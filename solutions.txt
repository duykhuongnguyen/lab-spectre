Part 1: Leaking Kernel Memory via Flush+Reload

Discussion Question 1: 256 cache lines need to be flushed, one for each possible byte value (0–255)

Discussion Question 2: If the attacker and victim do not share memory, Flush+Reload will not work, because it relies on shared memory pages being mapped into both address spaces. 
Without shared memory the attacker cannot flush the cache lines used by the victim and reload them to detect timing differences.

Part 2: Basic Spectre

Discussion Question 3: In a real-world Spectre attack, an attacker exploits speculative execution to bypass security boundaries and read arbitrary memory in the victim’s process or even in privileged address space (e.g., kernel memory). This is achieved by:
- Triggering speculation in victim code via indirect branches or bounds-checked accesses.
- Co-opting the victim to speculatively load data from a secret location into a shared cache-based side channel.
- Observing side effects (typically via Flush+Reload or Prime+Probe) to infer secret values.
The attacker must:
- Identify a vulnerable code gadget that performs a speculative memory access based on secret data.
- Control inputs to mistrain the branch predictor.
- Use shared microarchitectural state (e.g., cache) to recover leaked values.

Discussion Question 4: The minimum number of branch training iterations needed can vary by CPU model, branch predictor design, and system noise. In our experiments on the lab machine, the attack can succeed with ≥20 iterations.
